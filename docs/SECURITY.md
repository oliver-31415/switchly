# Security Policy

## Reporting a vulnerability
If you believe you have discovered a security vulnerability, please do not open a public issue immediately.

Instead, report it privately:
* Email: see `about_mail_address` in `app/src/main/res/values/strings.xml`

Please include:
* A clear description of the issue
* Steps to reproduce (if applicable)
* Potential impact
* Relevant logs, screenshots, or proof-of-concept details

Please avoid publicly disclosing vulnerabilities before a fix is available.

## Supported versions
Security fixes are generally applied to the latest version on the main branch.

Older releases may not receive updates or backported fixes.

## Scope
Examples of relevant reports include:
* Authentication or authorization issues
* unintended bypasses of blocking functionality
* exported component/security issues
* backup or data exposure problems
* privilege escalation or permission abuse
* sensitive information leaks

Non-security bugs, UI issues, or feature requests should be reported through the normal issue tracker instead.
